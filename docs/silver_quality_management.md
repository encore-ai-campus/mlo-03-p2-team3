# Silver 품질 관리 처리 내역

## 처리 기준과 실행

`src/quality_management.py`는 `data/02_silver/*.parquet`를 읽어 품질 규칙을 적용합니다. Silver 파일은 입력 전용으로 열며 수정하거나 덮어쓰지 않습니다. 결과는 모든 Silver 테이블에 대해 `data/02_silver/clean/`에 저장하고, 완전 중복 마권만 `data/02_silver/_excluded/BET_TICKET.parquet`에 따로 보관합니다.

품질 관리 단계 실행 시 `docs/품질관리.md`도 매번 다시 생성합니다. 보고서에는 규칙 목록, Bronze·Silver·clean의 차원별 위반 행 수와 비율, 규칙별 위반 건수 및 최대 3개의 예시 행을 기록합니다.

```powershell
python src/quality_management.py
```

모든 결과 행에는 `DQ_RULE_ID=DQ-U01`, 공통 `DQ_DECISION_ID=D-001`, Bronze 경로, `_SRC_ROW_NO`를 붙입니다. 이슈가 있는 행에는 별도의 이슈·조치 플래그를 추가해 원본 의미와 판단을 함께 보존합니다. 단일 입력 테이블은 Bronze 파일 순서로 행 번호를 복원하고, 진료 이력은 `VET_SEQ`, 진료명 브리지는 부모 `VET_SEQ`를 사용합니다. `RC_SALES` 두 결과는 Bronze 원본 행 순번으로 매핑합니다.

## 적용 규칙

처리 순서는 완전 중복 제거 후 이슈를 측정하고 플래그를 부여하는 순서입니다.

| 결정 ID | 처리 내용 | 저장 방식 |
|---|---|---|
| D-002 | BET_TICKET 완전 중복은 `_SRC_ROW_NO`가 가장 작은 행을 유지합니다. 동률은 Bronze 경로 오름차순으로 결정합니다. | 중복 행만 `_excluded/`에 저장하고 제외 사유를 기록합니다. |
| D-003 | 금액 0원 마권을 `INVALID_YN=Y`로 표시합니다. | `clean/`에 보존합니다. 매출과 취소율의 분자·분모 지표 포함 플래그는 N, 오류 집계 포함 플래그는 Y입니다. |
| D-004 | 취소 시각이 출발 시각 이상인 취소를 마권과 전표에 표시합니다. | 취소 분석에 포함합니다. 전표 건수는 고유 전표 행으로 계산하며 0원 늦은 취소도 별도 플래그로 셉니다. |
| D-005 | 빈 마권 마명은 출전표의 같은 경주·출전번호 마명으로 보정합니다. | `HR_NM_FILLED_YN=Y`와 `HR_NM_ORIG`로 보정 여부와 입력 이름을 보존합니다. |
| D-006 | 전표 마권 장수 불일치와 원전표 없는 취소를 각각 표시합니다. | `HEADER_MISMATCH_YN`, `ORIG_MISSING_YN`; 값은 수정하지 않습니다. |
| D-007 | 진료 조가 이전 스냅샷 조와 다르거나, 진료일 이전 스냅샷이 없으면 표시합니다. | 진료 이력 전체 건수를 보존하고 `VET_GROUP_ANALYSIS_STATUS=확인 필요`로 조·스냅샷 분석에서 식별합니다. |
| D-011 | 지정된 두 진료 기록의 일·열사병 유형을 유형별 집계에서 한 진료당 한 번 셉니다. | 원문 브리지 행은 보존하고 `VET_TYPE_AGG_NM`, `VET_TYPE_AGG_INCLUDE_YN`으로 집계 대상을 구분합니다. |

## 대사 및 로그

각 테이블은 `입력 행 수 = clean 행 수 + _excluded 행 수`를 검사합니다. 진료명 브리지는 원행을 보존하며, 집계 포함 행 수 1,662건을 별도로 확인합니다. 처리 내역은 `meta/dq_change_log.csv`, 행 수·이슈 기준 건수 대사는 `meta/dq_validation.csv`에 실행별로 누적합니다. 두 CSV는 UTF-8-SIG이며 이전 실행 기록 뒤에 추가됩니다.

## Gold 입력

Gold 작업은 `data/02_silver/clean/`만 입력으로 사용합니다. 팀원 4명은 동일 브랜치의 동일 Silver 버전을 기준으로 작업해야 합니다.
