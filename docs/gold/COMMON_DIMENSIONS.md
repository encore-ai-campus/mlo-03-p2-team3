# 공통 차원 통합 안건 (D-010)

- **D-010:** 각자 스타 스키마를 만든 뒤, Silver와 **공통 차원을 하나로** 합칩니다.
- 이 문서는 합칠 때 맞춰야 할 것을 차원별로 정리한 안건입니다.
- 다른 팀원 설계는 공유받은 설계 메모 기준이라, 실제 코드와는 다를 수 있습니다.

## 1. 어떤 차원을 누가 쓰나 (버스 매트릭스)

| 차원 | 출전 `FCT_RACE_ENTRY` (나) | 진료 `FCT_HORSE_MEDICAL` (세은) | 매출 `fact_bet_ticket` / `fact_actual_race_sales` (전희정) | 배팅·취소 `FCT_BET_CANCEL` |
|:--|:-:|:-:|:-:|:-:|
| 날짜 | ✅ DIM_DATE | ✅ DIM_DATE | ✅ dim_date | ✅ |
| 경주 | ✅ DIM_RACE | | ✅ dim_race | ✅ |
| 말 (SCD2) | ✅ DIM_HORSE | ✅ DIM_HORSE | | ✅ (구매일 이전 말 성적) |
| 조교사 / 조 | ✅ DIM_TRAINER | ✅ DIM_STABLE | | |
| 말 나이대 | (DIM_HORSE 안 `AGE_BAND_NM`) | ✅ DIM_AGE_GROUP | | |
| 승식 | | | ✅ dim_bet_type, dim_pool | ✅ |
| 회원 | | | ✅ dim_member | ✅ |
| 채널, 마권 상태 | | | ✅ dim_channel, dim_ticket_status | |
| 진료 유형 | | ✅ DIM_MEDICAL_TYPE | | |

**두 명 이상이 쓰는 차원이 공통 차원입니다.** 날짜, 경주, 말, 조교사·조, 나이대, 승식, 회원이 여기에 해당합니다. 혼자만 쓰는 차원(채널, 마권 상태, 진료 유형)은 담당자가 자유롭게 정하면 됩니다.

## 2. 모든 공통 차원에 공통으로 정할 것

| 항목 | 제안 |
|:--|:--|
| 담당자 | 차원마다 1명. 다른 사람은 담당자가 만든 파일을 그대로 씁니다 |
| 입력 | 같은 버전의 `data/02_silver/clean/` (D-012) |
| 대리키 | 자연키로 정렬한 순번(1부터). 난수·UUID는 쓰지 않습니다 (재실행해도 같은 키) |
| 이름 | 매핑 규칙서 2장 기준 UPPER_SNAKE와 주제어(`HR_`, `RC_`, `TR_` 등). 테이블은 `DIM_`, `FCT_` 대문자 |
| 타입 | Silver 타입 그대로 (날짜 DATE, 코드 VARCHAR, 금액 BIGINT 등) |
| 코드 값 | 매핑 규칙서 6장의 표준코드 그대로 (예: 성별 M/F/G) |
| 통합 후 | 차원 키가 바뀌면 각자 팩트의 외래키를 다시 연결합니다 |

## 3. 차원별 비교와 정할 것

### 3-1. DIM_DATE (4명 모두)

| | 나 | 세은 | 전희정 |
|:--|:--|:--|:--|
| 키 | `DATE_KEY` (YYYYMMDD 정수) | `DATE_KEY` | (dim_date) |
| 컬럼 | `FULL_DT`, `YEAR_NO`, `MONTH_NO`, `DAY_NO`, `DOW_NO`, `DOW_NM`, `WEEK_NO`, `RACE_DAY_YN` | `FULL_DT`, `YEAR_NO`, `MONTH_NO`, `DAY_NO` | 일·월·요일 |
| 범위 | 경주일 2026-05-22 ~ 11-14 (177일) | 진료일·보고일 | 발매일·경주일 |

**정할 것**
- **범위:** 모든 팩트 날짜를 덮어야 합니다. 최소 2026-05-16(첫 진료일) ~ 2026-11-18(마지막 보고일)입니다. 회원 생일·가입일까지 연결할지도 정해야 합니다.
- **컬럼:** 제 컬럼이 세은 님 컬럼을 모두 포함하니, 합집합으로 하자고 제안합니다.

### 3-2. DIM_RACE (나, 전희정, 배팅·취소)

| | 나 | 전희정 | 배팅·취소 |
|:--|:--|:--|:--|
| 자연키 | `RC_DT` + `RC_NO` (386행) | 경주 | 경주 |
| 필요한 속성 | 거리, 등급, 부담 방식, 날씨, 주로 상태, 함수율, 경주명, 출발 시각, 상금 | 등급, 조건, 거리, 날씨 | 출발 시각, 거리, 등급 |

**정할 것:** 속성은 합집합으로 합니다. 지금 제 DIM_RACE가 세 사람의 요구를 모두 포함합니다(출발 시각 `START_DTM` 포함).

### 3-3. DIM_HORSE (나, 세은, 배팅·취소) — 가장 중요

| | 나 | 세은 |
|:--|:--|:--|
| 자연키 | `HR_NM` | `HORSE_NM` |
| 속성 | 성별, 생일, 나이, 나이대, 등급, 조, 조교사, 외부마 여부, 마주, 부마, 모마 | 마명, 생일, 성별 |
| 버전 기간 | `VALID_FROM_DT`, `VALID_TO_DT`, `CURRENT_YN`, `SRC_SNAPSHOT_DT` | `VALID_FROM_DT`, `VALID_TO_DT` |
| 시점 기준 | 경주일 **이전**(엄격) 최근 스냅샷 | 진료 당시 |

**정할 것**
1. **컬럼 이름:** `HR_NM`(규칙서 주제어 HR) / `HORSE_NM` 중 하나. 제안: `HR_NM`
2. **"이전" 기준:** 이벤트일보다 엄격히 앞선 스냅샷(`<`)으로 할지. 제 방식은 `VALID_FROM_DT` = 스냅샷 다음 날입니다. 스냅샷 날짜와 경주일이 같은 날이 24일 있어서, `<`와 `<=`의 결과가 다릅니다.
3. **버전을 나누는 컬럼:** 제 기준은 성별·등급·나이·조·조교사·외부마 여부·마주입니다(4,126버전). 세은 님처럼 성별·생일만 쓰면 버전이 훨씬 적어집니다. 등급·조교사별 분석이 필요하면 제 기준이 필요합니다.
4. **성적(통산·1년 성적, 레이팅):** 차원에 넣지 않기로 제안합니다. 매주 바뀌어서 넣으면 버전이 약 22,000개가 됩니다. 배팅·취소의 "구매일 이전 승률"은 따로 만듭니다.
5. **스냅샷이 없는 경우:** 진료 71건은 진료일 이전 스냅샷이 없습니다. 차원에 연결하지 않고 `HORSE_MATCH_STATUS_CD` 등으로 표시합니다(D-007).

### 3-4. 조교사·조: DIM_TRAINER (나) ↔ DIM_STABLE (세은)

| | 나 `DIM_TRAINER` | 세은 `DIM_STABLE` |
|:--|:--|:--|
| 키 | `TRAINER_KEY` / 자연키 `TR_NM` | `STABLE_KEY` / `STABLE_NO` |
| 속성 | `TR_GRP_NO`, `TR_BIRTH_DT`, `DEBUT_DT` | `MEET_CD`, `STABLE_NO` |

데이터상 **조교사와 조(`TR_GRP_NO`)가 1:1**입니다(18명 = 18개 조). 여기에 외부마 조 `88`이 따로 있습니다.

**정할 것:** 하나로 합칠지(예: `DIM_TRAINER`에 조 번호·경마장 포함, 외부마 88 행 추가), 따로 두고 같은 키를 쓸지. 이름은 규칙서 기준 `TR_GRP_NO`로 맞추자고 제안합니다(`STABLE_NO` 대신).

### 3-5. 말 나이대: AGE_BAND_NM (나) ↔ DIM_AGE_GROUP (세은)

| | 나 | 세은 |
|:--|:--|:--|
| 형태 | DIM_HORSE 안의 컬럼 `AGE_BAND_NM` | 별도 차원 `DIM_AGE_GROUP` (`MIN_AGE`, `MAX_AGE`) |
| 구간 | 2~3 / 4~5 / 6~7 / 8세 이상 | (미정) |
| 나이 기준 | 스냅샷 `HR_AGE` (출전표 나이와 0건 차이) | 연 나이 / 만 나이 두 가지 |

**정할 것:** 구간, 나이 기준(연 나이 / 만 나이), 형태(차원으로 둘지 컬럼으로 둘지). 별도 차원으로 하기로 하면 제 팩트에 `AGE_GROUP_KEY`를 추가합니다.

### 3-6. 승식, 회원 (전희정, 배팅·취소)

- **승식:** 매핑 규칙서 6장에서 단승·단식 → WIN 등으로 이미 통일했습니다. `dim_bet_type`과 `dim_pool`을 **7개 코드짜리 DIM_BET_TYPE 하나**로 합치자고 제안합니다.
- **회원:** 자연키 `MBR_NO`. "현재 등급"(Type 1)으로 할지, 이력(SCD2)으로 할지 정해야 합니다. 배팅·취소의 50~59세 판정은 구매 시점 생일로 계산합니다.

## 4. 통합하면 내 팩트는 어떻게 되나

- **팩트 구조**(키 5개 + 측정값 4개)와 **측정값**은 바뀌지 않습니다.
- 공통 차원의 대리키가 바뀌면 **외래키 값만 다시 연결**합니다. `RACE_KEY`, `HORSE_KEY`, `TRAINER_KEY`, `DATE_KEY`가 대상입니다.
- 나이대를 별도 차원으로 하면 `AGE_GROUP_KEY`가 하나 추가됩니다.
- 연결은 자연키(경주일 + 경주번호, 마명 + 경주일, 조교사명)로 하므로 다시 만드는 데 문제가 없습니다.
